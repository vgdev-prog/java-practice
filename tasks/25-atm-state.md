# 18. Банкомат із станами

> Фаза E — сучасна Java та великий домен.

## Постановка

Банкомат поводиться по-різному залежно від поточного стану (чекає картку, чекає PIN, обирає операцію, видає гроші). Реакція на кожну подію делегується об'єкту-стану, а не вирішується великим `switch` усередині банкомата.

## Сутності та відповідальність

- **Контракт стану** — інтерфейс із методами на всі можливі події: вставити картку, ввести PIN, обрати операцію, скасувати. Кожен метод приймає сам банкомат, щоб стан міг перемкнути його на наступний стан.
- **Конкретні стани**:
  - *Чекає картку* — реагує лише на вставлення картки, переводить у «чекає PIN».
  - *Чекає PIN* — реагує лише на введення PIN.
  - *Обирає операцію* — реагує лише на вибір операції.
  - *Видає гроші* — заблокований для нових подій.
- **Банкомат** — тримає поточний стан (стартує з «чекає картку»), картку, сховище купюр. Усі публічні методи-події просто **делегують** виклик поточному стану. Уміє перемкнути стан.

## Поведінка / вимоги

- Банкомат **не містить** жодного `if (state == ...)` — уся логіка переходів живе в самих станах (State pattern замість великого `switch`).
- Виклик «не того» методу в певному стані (наприклад, ввести PIN, коли ще немає картки) → `IllegalStateException` зі зрозумілим повідомленням.

## Що тренує

State pattern: кожен стан — окремий клас зі своєю поведінкою, замість розгалуженого `switch` в одному місці.

## Acceptance criteria

- Банкомат не має жодного `if (state == ...)` — усе делеговано станам.
- Невірна подія для поточного стану → `IllegalStateException` зі зрозумілим текстом.
