# 9. Геометричні фігури

> Фаза B — інтерфейси, абстракції, поліморфізм.

## Постановка

Класична задача: різні фігури рахують площу й периметр кожна за своєю формулою, але через спільний контракт. Окремий аналізатор працює зі списком фігур: сумарна площа, найбільша фігура, підрахунок по типах.

## Сутності та відповідальність

- **Контракт фігури** — інтерфейс із двома методами: площа й периметр.
- **Конкретні фігури** — коло, прямокутник, трикутник (площа через формулу Герона), квадрат. Кожна — незмінний носій своїх параметрів (радіус; ширина й висота; три сторони; сторона) і реалізує контракт фігури.
- **Аналізатор фігур** — працює зі списком **базового типу `Shape`**:
  - сумарна площа всіх фігур;
  - фігура з найбільшою площею (на порожньому списку — виняток);
  - підрахунок «скільки фігур якого типу» (тип → кількість).

## Поведінка / вимоги

- Усі фігури — незмінні носії даних, а не звичайні класи з сеттерами.
- Сумарна площа рахується через Stream API (взяти потік, відобразити кожну фігуру в її площу, підсумувати).
- Конструктор трикутника валідує нерівність трикутника (сума двох сторін більша за третю); інакше — `IllegalArgumentException`.

## Що тренує

Інтерфейс + незмінний носій (типовий патерн Java 17+), Stream API (`mapToDouble`, `max`, `groupingBy`), валідацію в конструкторі.

## Acceptance criteria

- Усі реалізації фігур — незмінні носії даних.
- Сумарна площа — через стрім.
- Трикутник із некоректними сторонами не створюється: `IllegalArgumentException`.
