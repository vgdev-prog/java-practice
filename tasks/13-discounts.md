# 10. Система знижок

> Фаза C — патерни та узагальнення (дженерики).

## Постановка

На ціну товару накладається кілька знижок одна за одною. Кожна знижка — окрема взаємозамінна стратегія. Окрема «складена» знижка дозволяє зібрати кілька знижок у ланцюг і застосувати їх як одну.

## Сутності та відповідальність

- **Контракт знижки** — інтерфейс із одним методом: «застосуй до ціни, поверни нову ціну».
- **Конкретні знижки**:
  - *Фіксована* — віднімає певну суму (наприклад, −50 грн).
  - *Відсоткова* — віднімає певний відсоток (наприклад, −10%).
  - *BOGOF* («купи один — другий безкоштовно») — для простоти знижка 50% на загальну суму.
  - *Складена* — тримає список інших знижок і застосовує їх по черзі: результат однієї стає входом наступної.

## Поведінка / вимоги

- Якщо результат знижки став би від'ємним — повертається вихідна ціна (захист від некоректних знижок: ціна нижче нуля не буває).
- Складена знижка приймає список дочірніх знижок і зберігає його **незмінною копією** (`List.copyOf`).
- Усі грошові розрахунки — на `BigDecimal`.

## Що тренує

Strategy (кожна знижка — взаємозамінна стратегія) + Composite (набір знижок поводиться як одна знижка того ж контракту).

## Acceptance criteria

- Застосування знижки ніколи не дає від'ємну ціну — повертає вихідну, якщо вийшло б менше нуля.
- Складена знижка зберігає дочірні знижки незмінною копією списку.

## Очікувана поведінка (приклад)

```
ціна 200
складена[ відсоткова 10%, фіксована 50 ]:
  після 10%  → 180
  після −50  → 130
результат → 130
```
