# 1. Перевірка IBAN

> Фаза A — основи: один клас, типи, контракти.

## Постановка

Реалізувати валідатор IBAN-номера за алгоритмом **mod-97** (стандарт ISO 13616). Валідатор приймає рядок і відповідає, коректний це IBAN чи ні. Перевірка складається з трьох частин: правильна довжина для конкретної країни, допустимі символи (латинські літери й цифри), збіг контрольної суми.

## Сутності та відповідальність

- **Валідатор IBAN** — єдиний публічний клас. Назовні віддає один метод-питання «чи валідний цей рядок?», що повертає `true`/`false`. Усі допоміжні кроки (перевірка довжини, обчислення контрольної суми, перестановка символів, переклад літер у цифри) — приватні, назовні не стирчать.
- **Таблиця довжин по країнах** — статична незмінна константа всередині класу: код країни (`"UA"`, `"DE"`, …) → очікувана довжина IBAN. Для України — 29.

## Алгоритм (що має робити валідатор усередині)

1. Прибрати пробіли, привести до верхнього регістру.
2. Звірити довжину з таблицею для коду країни (перші 2 символи).
3. Перенести перші 4 символи в кінець рядка (rearrange).
4. Кожну літеру замінити на число: `A` = 10, `B` = 11, …, `Z` = 35. Цифри лишаються як є.
5. Отриманий великий рядок-число поділити на 97. Якщо залишок дорівнює 1 — IBAN валідний.

## Що тренує

Інкапсуляцію (усі допоміжні методи приватні), статичні константи, роботу зі `String` API, і `BigInteger` — бо число з 30+ цифр не влізає в `long`.

## Acceptance criteria

- Поля приватні, клас `final`.
- Жоден `if` не довший за 3 рядки.
- Жоден допоміжний метод не публічний.
- `UA213223130000026007233566001` → `true`.
- `UA213223130000026007233566002` → `false`.
- `"invalid"`, `null`, порожній рядок → `false` (без падіння).

## Очікувана поведінка (приклад)

```
isValid("UA213223130000026007233566001")  →  true
isValid("invalid")                         →  false
```
