# 2. Бібліотека книжок

> Фаза A — основи: один клас, типи, контракти.

## Постановка

Реалізувати бібліотеку, що зберігає книжки в кількох копіях. Книжку можна позичити (кількість доступних копій зменшується), повернути (збільшується назад), а також переглянути історію всіх позичань і повернень конкретної книжки.

## Сутності та відповідальність

- **Книжка** — незмінний носій даних: ISBN, назва, автор, рік видання. Нічого не вміє, лише тримає дані.
- **Запис історії** — незмінний носій: ISBN, читач, момент часу, дія (позичено / повернено).
- **Дія** — фіксований перелік із двох значень: «позичено» і «повернено».
- **Бібліотека** — головний клас. Усередині тримає три структури: книжки за ISBN, кількість доступних копій за ISBN, і список усіх записів історії. Назовні дає: додати книжку з N копіями, позичити, повернути, отримати історію по ISBN.

## Поведінка / вимоги

- Позичити книжку, якщо доступна хоч одна копія → копія зменшується, у історію додається запис «позичено».
- Позичити книжку, якщо копій 0 → кинути власний виняток (типу «немає доступних копій»).
- Повернути книжку → копія збільшується, у історію додається запис «повернено».
- Історія по ISBN віддається назовні **копією**, а не посиланням на внутрішній список (інакше зовнішній код зможе її змінити).

## Що тренує

Незмінні носії даних, мапи (ISBN → книжка, ISBN → кількість), фіксовані переліки значень, журнал подій (event log), захист внутрішніх колекцій.

## Acceptance criteria

- Книжка й запис історії — незмінні носії даних (не звичайні класи з сеттерами).
- Не можна позичити книжку, копій якої немає — кидається власний виняток.
- Метод історії повертає незмінну копію списку, а не внутрішню колекцію.

## Очікувана поведінка (приклад)

```
addBook("Effective Java" / ISBN 978-1, копій 3)
borrow(978-1, "Vlad")     → копій 2, історія += [позичено Vlad]
borrow(978-1, "Olena")    → копій 1, історія += [позичено Olena]
returnBook(978-1, "Vlad") → копій 2, історія += [повернено Vlad]
historyOf(978-1)          → 3 записи в порядку подій
```
