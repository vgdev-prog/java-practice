# 27. Планувальник зустрічей (java.time)

> Фаза D — стандартна бібліотека: стріми, I/O, regex, час.

## Постановка

Реалізувати розклад зустрічей. Зустріч має початок і тривалість. Розклад уміє перевіряти, чи перетинаються дві зустрічі, шукати вільне вікно заданої тривалості й рахувати сумарний зайнятий час. Уся робота з часом — лише через `java.time`.

## Сутності та відповідальність

- **Зустріч** — незмінний носій: момент початку (`LocalDateTime`) і тривалість (`Duration`). За потреби вміє віддати момент завершення (початок + тривалість).
- **Розклад** — тримає список зустрічей. Уміє:
  - сказати, чи перетинаються дві зустрічі (накладання інтервалів у часі);
  - додати зустріч лише якщо вона не конфліктує з наявними;
  - знайти найближче вільне вікно заданої тривалості після певного моменту;
  - порахувати сумарний зайнятий час за день (`Duration`).
- (Опційно) робота з часовими поясами через `ZonedDateTime`, якщо учасники в різних зонах.

## Поведінка / вимоги

- Тільки **`java.time`** — жодних старих `Date`/`Calendar`.
- Типи `java.time` незмінні: будь-яка «зміна» повертає новий обʼєкт (наприклад, `start.plus(duration)`).
- Перетин інтервалів рахувати коректно (дві зустрічі конфліктують, якщо одна починається до кінця іншої й навпаки).
- Тривалості — через `Duration`; різниці в днях/місяцях — через `Period`.

## Що тренує

`LocalDateTime`, `Duration`, `Period`, (опц.) `ZonedDateTime`, незмінність типів часу, логіку перетину інтервалів, коректні розрахунки замість «магічних» мілісекунд.

## Acceptance criteria

- Перетин двох зустрічей визначається коректно (включно з межовими випадками «впритул»).
- Конфліктна зустріч у розклад не додається.
- Пошук вільного вікна повертає коректний момент або ознаку «немає вікна».
- Сумарний зайнятий час рахується через `Duration`.

## Очікувана поведінка (приклад)

```
зустріч A: 10:00 + 1h  (до 11:00)
зустріч B: 10:30 + 1h
overlaps(A, B)  → true
add(B) до розкладу з A → відхилено (конфлікт)
freeSlotAfter(11:00, 30min) → 11:00
busyTime() → 1h (лише A додано)
```
