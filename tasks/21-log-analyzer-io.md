# 21. Аналізатор логів (термінал + файли)

> Фаза D — стандартна бібліотека: стріми, I/O, regex, час.

## Постановка

Консольна утиліта, що читає текстовий лог-файл, рахує статистику по рівнях (ERROR / WARN / INFO / DEBUG) і пише звіт у вихідний файл. Шлях до файлу береться або з аргументів запуску, або інтерактивно з термінала. Великий файл не можна цілком тримати в пам'яті.

## Сутності та відповідальність

- **Джерело вводу** — відповідає за отримання шляху до файлу: спершу дивиться на аргументи запуску, якщо їх немає — питає інтерактивно через термінал.
- **Запис логу** — незмінний носій розібраного рядка: рівень, момент часу, джерело, повідомлення.
- **Парсер рядка** — перетворює сирий рядок логу на запис; некоректні рядки відкидає або рахує окремо.
- **Аналізатор** — рахує статистику: скільки рядків кожного рівня, скільки нерозпізнаних.
- **Записувач звіту** — пише підсумок у вихідний текстовий файл.
- (Опційно) **власний ресурс, що закривається** — якщо обгортаєш читання у свій клас, реалізуй `AutoCloseable`, щоб він працював у try-with-resources.

## Поведінка / вимоги

- Шлях до файлу: якщо переданий аргументом — беремо його; інакше читаємо з термінала.
- Великий файл читати **лінивим потоком рядків** (`Files.lines`), а не вантажити весь у список — інакше O(n) по пам'яті на мільйонах рядків.
- Усі ресурси (потоки, читачі) закривати через **try-with-resources**, не вручну в `finally`.
- Явно вказувати кодування **UTF-8** (не покладатись на системний дефолт).
- `IOException` обробляти усвідомлено: не ковтати, давати зрозуміле повідомлення (oop.md §8).
- Памʼятати про пастку `Scanner` (`nextInt` лишає `\n` у буфері) — якщо змішуєш числовий і рядковий ввід.

## Що тренує

`java.nio.file` (`Path`, `Files.lines`, `Files.write`), термінальний ввід (`args`, `Scanner` / `BufferedReader`), try-with-resources, `AutoCloseable`, лінивість потоку рядків і її вплив на памʼять (Big O), кодування.

## Acceptance criteria

- Файл не вантажиться цілком у памʼять без потреби (`Files.lines`, а не `readAllLines` для великих обсягів).
- Усі ресурси закриті через try-with-resources.
- Кодування задано явно (UTF-8).
- Жодного проковтнутого `IOException`.
- Працює і з аргументом-шляхом, і з інтерактивним вводом.

## Очікувана поведінка (приклад)

```
$ java LogAnalyzer app.log report.txt
Оброблено рядків: 1 000 000
  ERROR: 1 245
  WARN : 8 730
  INFO : 989 012
  нерозпізнано: 1 013
Звіт записано у report.txt
```
