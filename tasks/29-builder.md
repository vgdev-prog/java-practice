# 29. Конструктор HTTP-запиту (Builder)

> Фаза F — патерни проектування (Gang of Four). Породжувальний.

## Постановка

Скласти складний незмінний обʼєкт із багатьма полями (частина обовʼязкові, більшість опційні) через **текучий (fluent) білдер**, замість конструктора-телескопа на 8 параметрів.

## Сутності та відповідальність

- **HTTP-запит** — незмінний результат: метод, URL (обовʼязкові), заголовки, тіло, таймаут, query-параметри (опційні). Створюється **тільки** через білдер; власний конструктор прихований.
- **Білдер** — накопичує параметри ланцюгом викликів (`method(...).header(...).body(...)`), кожен повертає сам білдер. Метод `build()` валідує й повертає готовий незмінний запит.

## Поведінка / вимоги

- Білдер дозволяє задавати поля в будь-якому порядку, опускати опційні.
- `build()` валідує обовʼязкові (метод і URL не `null`); інакше — `IllegalStateException`/`IllegalArgumentException`.
- Результат **незмінний**: після `build()` запит не міняється; колекції-поля (заголовки) — незмінні копії.
- Кожен метод-сетер білдера повертає `this` для ланцюга.

## Що тренує

Builder для уникнення «телескопічних» конструкторів і опційних параметрів, незмінність результату, валідацію на межі `build()`, текучий API.

## Acceptance criteria

- Власний конструктор запиту недоступний — лише через білдер.
- Поля задаються в довільному порядку, опційні можна пропустити.
- `build()` без обовʼязкових полів кидає виняток.
- Результат незмінний, колекції — незмінні копії.

## Очікувана поведінка (приклад)

```
HttpRequest req = HttpRequest.builder()
    .method("POST")
    .url("https://api.example.com/orders")
    .header("Content-Type", "application/json")
    .body("{...}")
    .timeout(Duration.ofSeconds(5))
    .build();
```
