# 22. Семантична версія (equals / hashCode / Comparable)

> Фаза A — основи: один клас, типи, контракти.

## Постановка

Реалізувати клас семантичної версії (`1.2.3`), який коректно поводиться як ключ у `HashMap`/елемент `HashSet`, правильно порівнюється на рівність і має природний порядок сортування. Окремо — альтернативне сортування через зовнішній компаратор.

> **Навмисно:** спершу напиши це **звичайним класом** і реалізуй `equals`/`hashCode` **руками**, щоб відчути контракт. Потім зроби варіант через `record` і порівняй, що компілятор згенерував за тебе.

## Сутності та відповідальність

- **Версія** — незмінний носій: major, minor, patch (за бажанням — pre-release мітка). Тримає три числа й нічого не мутує.
- **Рівність** — дві версії рівні, якщо рівні всі компоненти. Реалізувати узгоджені `equals` і `hashCode`.
- **Природний порядок** — реалізувати `Comparable`: спершу за major, далі minor, далі patch.
- **Альтернативні порядки** — окремі `Comparator`-и (наприклад, за спаданням, або спершу за patch).

## Поведінка / вимоги

- Контракт `equals`: рефлексивність, симетрія, транзитивність, узгодженість, коректність для `null`.
- **Головне правило:** якщо `equals` дає `true` — `hashCode` обовʼязково однаковий. Інакше `HashMap`/`HashSet` ламаються (обʼєкт «зникає» з мапи).
- Покладені у `HashSet` однакові версії схлопуються в одну (дублікат не зберігається).
- `TreeSet` із версіями зберігає їх у відсортованому природному порядку.

## Що тренує

Контракти `equals`/`hashCode`, `Comparable` (природний порядок) vs `Comparator` (зовнішній порядок), розуміння, що саме `record` робить автоматично.

## Acceptance criteria

- Рівні версії мають рівний `hashCode`.
- `HashSet` прибирає дублікати версій.
- Сортування через `Comparable` і через `Comparator` дають різні (очікувані) порядки.
- Версія незмінна; написана спершу руками, потім — варіант через `record` для порівняння.

## Очікувана поведінка (приклад)

```
new Version(1,2,3).equals(new Version(1,2,3))  → true
однаковий hashCode у рівних версій             → так
Set.of(1.0.0, 1.0.0, 2.0.0).size()             → 2
sort природний: [1.0.0, 1.2.0, 2.0.0]
sort за спаданням (Comparator): [2.0.0, 1.2.0, 1.0.0]
```
