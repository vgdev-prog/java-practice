# 20. Симуляція автостоянки

> Фаза E — сучасна Java та великий домен.

## Постановка

Змоделювати автостоянку з різними типами місць (мото, авто, для людей з інвалідністю, з зарядкою). Авто заїжджає → стоянка шукає перше відповідне вільне місце → видається талон. На виїзді рахується тариф за стратегією.

## Сутності та відповідальність

- **Тип транспорту** — фіксований перелік: мото, авто, для людей з інвалідністю, електро.
- **Паркомісце** — абстрактна основа: тримає ідентифікатор і стан «зайнято/вільно», уміє зайнятись і звільнитись, і відповідає, який тип транспорту приймає. Підкласи — місце для мото, для авто, для людей з інвалідністю, електро (останнє додатково знає, чи є зарядка).
- **Талон** — незмінний носій: ідентифікатор місця й момент в'їзду.
- **Контракт тарифікації** — інтерфейс: порахувати плату за талоном, моментом виїзду й типом транспорту (взаємозамінна стратегія тарифу).
- **Стоянка** — тримає список місць і стратегію тарифікації. Уміє: припаркувати транспорт заданого типу (повертає `Optional` талона — порожній, якщо вільних місць немає) і оформити виїзд (порахувати плату й звільнити місце).

## Поведінка / вимоги

- Паркування повертає `Optional<Ticket>`, **ніколи не `null`** (порожній Optional = немає місця).
- Доменні правила розміщення:
  - авто для людини з інвалідністю може стати на спеціальне місце **або** на звичайне авто-місце;
  - електро на місці з зарядкою отримує знижку, на звичайному авто-місці — звичайний тариф.
- Стоянка обирає **перше відповідне вільне** місце.

## Що тренує

Велику композицію, `Optional` як «може не бути», стратегію тарифу, реалістичне доменне моделювання.

## Acceptance criteria

- Паркування повертає `Optional<Ticket>`, не `null`.
- Авто для людини з інвалідністю паркується на спецмісце або на авто-місце.
- Електро на місці з зарядкою — зі знижкою, на авто-місці — звичайний тариф.
