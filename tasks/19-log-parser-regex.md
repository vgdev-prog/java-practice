# 26. Парсер та валідатор (regex)

> Фаза D — стандартна бібліотека: стріми, I/O, regex, час.

## Постановка

Реалізувати розбір структурованих текстових рядків і валідацію форматів через регулярні вирази (`Pattern` / `Matcher`). Наприклад: розбір рядка логу на компоненти й перевірка коректності email і телефону.

## Сутності та відповідальність

- **Скомпільовані шаблони** — `Pattern`-и як `static final` константи: компілюються **один раз** при завантаженні класу, а не на кожен виклик (інакше марно витрачаємо ресурси на повторну компіляцію).
- **Парсер рядка логу** — бере рядок виду `[2026-06-30 12:00:01] ERROR UserService: повідомлення`, через `Matcher` і **іменовані групи** дістає момент, рівень, джерело, текст; повертає структурований запис або «не розпізнано».
- **Валідатори** — окремі методи, що відповідають `true`/`false`: чи валідний email, чи валідний телефон (формат UA), тощо.

## Поведінка / вимоги

- `Pattern` компілюється один раз і зберігається в `static final` — не створювати його в тілі методу.
- Використати **іменовані групи** (`(?<level>...)`) для читабельного доступу до частин.
- Чітко розрізняти `matches()` (шаблон має покрити **весь** рядок) і `find()` (шукає **підрядок**).
- Некоректний рядок не валить програму — повертається ознака «не розпізнано».

## Що тренує

`Pattern`/`Matcher`, іменовані групи, різницю `matches()` vs `find()`, продуктивність (компіляція шаблону один раз), парсинг тексту в структуру.

## Acceptance criteria

- Шаблони — `static final`, компілюються один раз.
- Валідні рядки коректно розбираються у структуру через іменовані групи.
- Невалідні рядки відсіюються без падіння.
- Валідатори email/телефону повертають коректний `boolean`.

## Очікувана поведінка (приклад)

```
parse("[2026-06-30 12:00:01] ERROR UserService: збій")
  → {час: 2026-06-30 12:00:01, рівень: ERROR, джерело: UserService, текст: збій}
isValidEmail("vlad@example.com")  → true
isValidEmail("not-an-email")      → false
```
