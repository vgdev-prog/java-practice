# 15. Кеш із політикою витіснення

> Фаза C — патерни та узагальнення (дженерики).

## Постановка

Реалізувати кеш фіксованого розміру з парою «ключ → значення». Базова логіка читання/запису однакова; підкласи відрізняються **лише політикою**, що саме викидати, коли кеш переповнений.

## Сутності та відповідальність

- **Кеш** — абстрактна узагальнена основа на двох параметрах типу (ключ, значення). Тримає максимальний розмір і внутрішнє сховище. Дає **готові, незмінні** методи читання й запису: при записі, якщо сховище заповнене, спершу викликається витіснення, потім кладеться нове значення. Сам спосіб витіснення — абстрактний, його доозначує підклас (шаблонний метод).
- **Конкретні політики**:
  - *LRU* — викидає те, що найдовше не використовували.
  - *FIFO* — викидає те, що додали найраніше.
  - *TTL* — викидає все, чий час життя минув (тримає тривалість життя елемента).

## Поведінка / вимоги

- Метод запису — `final` у базі: підкласи його **не перевизначають**, лише задають витіснення.
- Абстрактним лишається тільки витіснення; решта логіки спільна.
- LRU зручно зробити на `LinkedHashMap` із режимом `accessOrder = true`.

## Що тренує

**Template Method** (запис фіксований у базі, витіснення різне в підкласах), дженерики на двох параметрах типу.

## Acceptance criteria

- Метод запису позначений `final` — підкласи його не чіпають.
- Абстрактний лише метод витіснення.
- LRU реалізований через `LinkedHashMap` з `accessOrder = true`.
