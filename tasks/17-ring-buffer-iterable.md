# 25. Кільцевий буфер (власний Iterable / Iterator)

> Фаза C — патерни та узагальнення (дженерики).

## Постановка

Реалізувати кільцевий буфер (ring buffer) фіксованої місткості: при переповненні новий елемент затирає найстаріший. По буферу можна ходити циклом `for-each` — від найстарішого елемента до найновішого. Для цього клас має сам реалізувати механізм перебору.

## Сутності та відповідальність

- **Кільцевий буфер `<T>`** — узагальнений клас фіксованої місткості. Уміє: додати елемент (із затиранням найстарішого при переповненні), спитати розмір, реалізує `Iterable<T>`, щоб працювати в `for-each`.
- **Власний ітератор `<T>`** — внутрішня реалізація `Iterator<T>`: відповідає на «чи є наступний», віддає наступний у логічному порядку (від найстарішого), кидає `NoSuchElementException`, коли елементи скінчились.

## Поведінка / вимоги

- `for-each` по буферу працює саме тому, що клас реалізує `Iterable` (це і є контракт, який ховається за синтаксисом `for (var x : buffer)`).
- Обхід іде в логічному порядку (найстаріший → найновіший), а не за фізичним розташуванням у масиві.
- `next()` після останнього елемента → `NoSuchElementException`.
- Дженерик-типобезпека: жодних кастів до `Object`.

## Що тренує

Контракти `Iterable`/`Iterator`, розуміння, **як насправді працює `for-each`** під капотом, дженерики, інкапсуляцію кільцевої логіки (індекси «голови» й «хвоста»).

## Acceptance criteria

- Клас реалізує `Iterable<T>`, `for-each` по ньому компілюється й працює.
- Обхід у правильному (логічному) порядку.
- `next()` на вичерпаному ітераторі → `NoSuchElementException`.
- При переповненні найстаріший елемент затирається, розмір не перевищує місткості.

## Очікувана поведінка (приклад)

```
buffer місткості 3
add(1), add(2), add(3)   → [1, 2, 3]
add(4)                   → [2, 3, 4]   (1 затерто)
for (var x : buffer)     → 2, 3, 4
```
